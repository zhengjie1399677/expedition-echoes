# 《远征余响》代码审查标准与流程

> 状态：生效中（2026-08-06 制定，2026-08-07 重建恢复）。代码合入与功能交付前的审查依据。
> 与 [PROJECT_DEVELOPMENT_GUIDE.md](PROJECT_DEVELOPMENT_GUIDE.md) 的关系：**前者管「怎么做对」，本文管「怎么确认做对了」**。本文所有红线均引用该指导的既有边界，不新增设计。

## 1. 文档定位

- `PROJECT_DEVELOPMENT_GUIDE.md` 定义北极星、架构职责、状态/存档规则与功能实施流程——它是「做对」的施工图。
- 本文把上述边界转成**可判定的审查动作**：分级、维度、红线、流程与报告约定——它是「确认做对」的验收尺。
- 二者冲突时以 `PROJECT_DEVELOPMENT_GUIDE.md` 为准；本文只负责判定，不改变规则。

## 2. 三级分级

| 级别 | 含义 | 合入影响 |
|---|---|---|
| 🔴 **Blocker** | 必须修。违反红线、破坏核心规则正确性、数据安全或玩家可玩性 | 阻塞合入 |
| 🟡 **Suggestion** | 应修。影响体验、维护性或覆盖缺口，但不破坏正确性 | 可带修复计划合入，当周闭环 |
| 💭 **Nit** | 风格、命名、排版等主观问题 | 不阻塞，随缘清理 |

### 2.1 判定决策树

```text
违反红线速查（§7 十五条之一）？─────────────────────────► 🔴 Blocker
否
导致存档丢失/损坏、旧档卡死、玩家无法继续？─────────────► 🔴 Blocker
否
核心规则（金币/伤害/掉落/事件结果/补给消耗）与设计不符？─► 🔴 Blocker
否
LLM 越权（写状态/发未定义物/跳过前置/确认完成）？───────► 🔴 Blocker
否
影响体验但可绕过、仅缺反馈、死代码、测试缺口？─────────► 🟡 Suggestion
否
纯风格/命名/排版/可读性问题？────────────────────────► 💭 Nit
```

### 2.2 历史判例表（以 2026-08-06 全项目审查 26 项为基准）

| 判例 | 问题性质 | 判定 | 判定理由 |
|---|---|---|---|
| 威胁预告 UI 缺失（敌人意图不渲染） | 高严重 | 🔴 Blocker | 核心「读题→解题」玩法在玩家界面是空的，体验链路断裂 |
| 事件补给白嫖（recover 不校验 requirement/不扣消耗） | 逻辑错误 | 🔴 Blocker | 奖励/消耗与设计不符，玩家可白嫖，规则正确性被破坏 |
| 结算瞬间弹空壳晨报（pending 未处理） | 逻辑错误 | 🟡 Suggestion | 显示错误但不破坏存档正确性 |
| 背包面板 key 大小写错误 + 错读数据源 | 逻辑错误 | 🟡 Suggestion | 功能可用但展示数据错误，可绕过 |
| 死 action 仅测试驱动（SWAP/DEESCALATE 等） | 失效/废弃 | 🟡 Suggestion | 不破坏正确性，但增加维护面与误导 |
| 错误类 9 个仅测试引用 | 失效/废弃 | 🟡 Suggestion | 同上 |
| 城门锁定态可点击（交互误导） | 未完成/占位 | 🟡 Suggestion | 影响引导但无数据风险 |
| 装备图标 emoji 占位 | 未完成/占位 | 💭 Nit | 视觉占位，不阻塞功能 |
| 无效导入 / 死 prop / 多余导出 | 失效/废弃 | 💭 Nit | 纯卫生问题 |

## 3. 分级审查

按**改动规模与影响面**选档，避免一刀切：小改动不拖全流程，大改动不许漏检。

| 档位 | 触发条件 | 覆盖 |
|---|---|---|
| **全面审查** | 跨层改动（domain + ui + infrastructure + content）；存档契约变更；新系统/新页面；新增或修改 Phaser 场景；重构涉及规则 | 全部 9 个维度（§4），AI + 人工交叉审查，跑完整机器检查 |
| **标准审查** | 单层改动：领域规则 + 测试；UI 组件增改（不触及核心规则）；content 内容增改 | 维度 1/4/7 必查，其余按改动面抽查 |
| **轻量审查** | 纯文案、样式微调、重命名（带迁移则升档）、死代码删除、单文件小改 | 自审 + 机器检查；对照 §7 十五条速查 + §6 写作规范 |

默认走**标准审查**；拿不准时升档不降档。涉及 Phaser、存档迁移、LLM 通道的改动一律**全面审查**。

## 4. 九个审查维度

每个维度：**项目红线**（违反即 🔴）+ **常见问题**（多为 🟡/💭，供快速对号）。

### 维度 1：领域规则与数值正确性
**红线**
- 金币/经验/生命/压力/补给/装备/掉落/任务完成的计算不在 domain reducer 内（出现在 ui/组件/Phaser 中）→ 🔴
- 数值与设计文档（GDD / BALANCE_TABLE / COMBAT_INTENT_SYSTEM）不符且无设计变更记录 → 🔴
- 事件选择无可见落点（结算/日志/后续状态均无痕迹）→ 🔴
- 事件未提供至少两种可理解的选择，或未明确收益/代价/风险 → 🔴

**常见问题**
- 装备加成只显示「看起来有加成」，未进入领域计算（GUIDE §5.3）
- recover/结算分支不兑现 requirement、不扣消耗 → 白嫖（判例 L2）
- 数值硬编码在组件；边界（0 生命、资源不足、重复 action）未处理
- 日志/文案与真实数值不符（all_damage 虚高、risk_fight 文案与掉落不符）

### 维度 2：架构职责与分层边界
**红线**
- `domain` 访问 React / DOM / `localStorage` / 网络 / LLM → 🔴
- `content` 读取运行状态或执行随机逻辑 → 🔴
- `infrastructure` 决定游戏规则 → 🔴
- `ui` 组件内计算并写入核心规则（金币/伤害/掉落/事件结果）→ 🔴
- 两个以上页面复制同一规则/同一数值而未抽到 domain/content → 🔴

**常见问题**
- 规则直接写进 `App.tsx`；用一次性 CSS 覆盖掩盖结构问题（GUIDE §7）
- 组件内 import domain 后重算一份结果，与真实状态分叉
- 解析器/适配器直接 dispatch，未经领域校验

### 维度 3：LLM 边界与降级
**红线**
- LLM 输出直接写入游戏状态，或自行确认「任务完成」→ 🔴
- LLM 发放未定义的道具、数值、角色或区域 → 🔴
- 结构化输出未走「提取 → 格式校验 → 白名单/语义校验 → 领域 action」→ 🔴
- 依赖 LLM 的互动无双通道（固定对白 + LLM 深聊）→ 🔴
- LLM 不可用时核心流程不可玩（无本地降级台词）→ 🔴
- LLM 请求无上下文/输出上限，且结果不缓存（刷新重复消耗）→ 🔴

**常见问题**
- 打开任务/区域/结算/宿舍时自动为三名角色分别请求模型（GUIDE §5.5）
- LLM 返回数值被 UI 直接采用，未过白名单/语义校验
- 解析失败无本地修复或安全回退路径

### 维度 4：状态、存档与迁移
**红线**
- 新增/变更持久字段未同步：类型+初始状态、`storage.ts` 安全默认值与清洗、版本范围与旧 key 策略、对应测试 → 🔴
- 用「读不到字段就重置整档」替代迁移（除非存档已无法安全解析）→ 🔴
- 新字段导致玩家旧档卡死 → 🔴
- 字段改名（如 morale → 压力）未带迁移与测试，只改显示文字 → 🔴

**常见问题**
- `SUPPORTED_VERSION_MIN` 与迁移链不一致（当前基线 v12，SUPPORTED_VERSION_MIN=12，勿回退）
- 旧档/缺字段/非法字段三类测试缺失
- 跨过 `storage.ts` 直接读写 `localStorage`
- 迁移链残留大量死 key（V5–V11 已收缩，勿复活）

### 维度 5：UI 展示、交互与反馈
**红线**
- UI 显示的数值非领域层最终结果（另复制一套独立计算）→ 🔴
- 结算/结果不展示消耗、返还与收益，让玩家猜规则 → 🔴
- 关键操作被遮挡/无法触发；无禁用/空态/错误提示 → 🔴
- 新按钮缺默认/悬停/禁用/键盘焦点状态，文字对比度不足 → 🔴

**常见问题**
- 空壳晨报/空壳面板在结算瞬间弹出（pending 状态未处理）
- 锁定态可点击（城门引导失效）；16:9 与窄窗口未检查
- emoji/菱形占位图标（如无资源，先标注待美术，不得假装完成）

### 维度 6：Phaser 生命周期与表现
**红线**
- 新增/修改 Phaser 场景未走 `BattleCanvasBoundary` + 延迟创建模式（React 19 StrictMode 下 unmount/remount 竞态）→ 🔴（黑屏类 bug 高发区）
- Phaser 拥有战斗真相或在场景内重算战斗结果（真相必须保留在 domain）→ 🔴
- 表现与 domain 结算不一致（如动画只表现单体、实际多目标掉血）→ 🔴
- 效果不可读（无法分辨普攻/技能/受击/治疗/战斗结束）→ 🔴

**常见问题**
- 组件卸载后异步回调 setState（缺 cancelled 标志/非ce 消费）
- 引用未预加载纹理；引用不存在的 rig/路径（死代码）
- 反馈 effect 缺依赖项 → 首帧后失效的回归（判例 L1）

### 维度 7：测试覆盖与可验证性
**红线**
- 领域规则变更无对应测试 → 🔴
- 存档/迁移变更无旧档/缺字段/非法字段测试 → 🔴
- 新 action 无重复 action、非法 action、资源不足边界测试 → 🔴
- 测试断言为空或恒真（无实质 expect）→ 🔴

**常见问题**
- 只测正常路径，缺边界/回收/回归覆盖
- 测试仅驱动死代码（action/类/字段无生产引用）→ 判 🟡 并标记清理
- flaky 测试（依赖时序/随机/外部资源）：必须隔离或修复，不得污染 CI 信号
- 测试命名不表达行为（`test('works')`）

### 维度 8：内容与资源完整性
**红线**
- 新增资源未同时说明来源、用途、上限与玩家取舍（只有来源无消耗）→ 🔴
- 为填空而增加无来源无用途的资产 → 🔴
- 假透明（RGB 棋盘格）、AI 水印、半透明黑底素材入库 → 🔴
- 代码引用不存在的纹理/路径 → 🔴

**常见问题**
- 素材 RGB 无 alpha 却显示「棋盘格透明」；非像素立绘缺边缘过渡
- 大体积 PNG 未压缩（world/ 场景图应 webp q82）
- 像素风（pixel/）二值化 alpha 是风格特性，不按锯齿误报（MEMORY 美术规范）
- 新增素材未过 `scripts/check_alpha.py`

### 维度 9：提交与工程卫生
**红线**
- 一次提交混杂机制改动 + 全面格式化 + 无关美术 → 🔴
- 重构改变规则未明确为「玩法改动」并补测试 → 🔴
- 临时方案无退出条件（会沉淀为永久债务）→ 🔴

**常见问题**
- 死代码/无效导入/多余导出残留（判 🟡）
- 大面积格式化混入功能提交，diff 不可审
- 覆盖/重置他人未提交改动；revert 误伤范围
- 提交信息不说明「改了什么 + 为什么」

## 5. 审查流程

```text
自审清单 → 机器检查 → AI + 人工交叉审查 → 合入门槛（0 Blocker）→ 记录复盘
```

### 5.1 自审清单（开发者提交前）
- [ ] 红线速查 15 条（§7）逐条过，无红线级问题
- [ ] 需求对应 Story/GDD 验收标准可逐条勾选
- [ ] 分层边界：改动落在正确目录，无跨层越权
- [ ] 相关测试已写或已更新（含边界与非法输入）

### 5.2 机器检查
```powershell
npm test          # vitest run：领域 + 基础设施测试
npm run build     # tsc -b + vite build：类型 + 产物
```
- 三项全绿才进入人工审查；任一红即未达 QA。
- `npm run build` 直接执行即可（safe-delete 插件已从 vite.config.ts 移除）。若未来再遇 dist 清理失败，用 `vite build --outDir dist-verify --emptyOutDir false` 验证产物。
- **环境限制（safe-delete）**：删除文件一律用单条 `Remove-Item -LiteralPath <file> -Force -ErrorAction SilentlyContinue`；**禁止 git rm 批量删含未入库文件的目录**（会级联删除整个目录，未跟踪文件永久丢失，曾致 CODE_REVIEW_STANDARD.md 误删）。

### 5.3 AI + 人工交叉审查
- 按分级档位（§3）跑对应维度；AI 负责静态扫描 + 交叉引用 + 断言统计，人工负责体验判定与设计意图核对。
- 每条意见按 §6 写作规范落笔，编号引用。

### 5.4 合入门槛
- **0 Blocker** 才允许合入；🟡 可带修复计划合入（当周闭环）；💭 不阻塞。
- 涉及存档迁移、LLM 通道、Phaser 场景的改动，合入前必须人工确认浏览器实测无新 console 错误。

### 5.5 记录复盘
- 产出审查报告 `docs/CODE_REVIEW_YYYY-MM-DD.md`（命名约定见 §8）。
- 复盘沉淀：新红线入 §4/§7，新判例入 §2.2，环境坑入项目记忆。

## 6. 意见写作规范

一条合格审查意见必须同时满足：

1. **定位到行**：`文件:行号`，如 `src/ui/BattleCanvas.tsx:635`；不写「某文件有问题」。
2. **说清后果**：指出影响面——数据正确性 / 玩家可玩性 / 维护成本，并说明「为什么这是问题」。
3. **给可执行建议**：具体改法（补参数、加校验、删代码、抽模块），而非「请优化」。
4. **一条一主题**：每条意见只谈一个问题；复合问题拆多条。
5. **标注分级 + 编号**：🔴 B1 / 🟡 S1 / 💭 N1，报告内连续编号便于引用（也可加类型前缀 L/U/D 表示逻辑/未完成/死代码）。

反例：`Expedition.tsx 这里逻辑有点乱，建议重构。`
正例：`src/ui/pages/Expedition.tsx:245 技能槽硬编码 1 个启用、其余 disabled；后果：多技能系统（skills[]）在 UI 只暴露一个，玩家无法使用第二个技能；建议：按 activeHero.skills.slice(0,2) 动态渲染，并为越界情况补空态。🟡 S3`

## 7. 红线速查 15 条（提交/合入前逐条过）

1. LLM 输出直接写入游戏状态，或自行确认「任务完成」。
2. LLM 发放未定义的道具/数值/角色/区域。
3. `domain` 访问 React / DOM / `localStorage` / 网络 / LLM；`content` 读运行状态。
4. `ui`/Phaser 组件内计算并写入金币/伤害/掉落/事件结果（绕过领域）。
5. Phaser 拥有战斗真相，或在场景内重算战斗结果。
6. 持久字段变更未同步：类型+初始状态 / `storage.ts` / 版本 / 测试。
7. 用「重置整档」替代迁移；新字段导致旧档卡死。
8. 新增资源未说明来源/用途/上限/取舍；为填空加资产。
9. 装备/数值只显示在 UI，未进入领域计算。
10. LLM 互动无双通道，或降级后核心流程不可玩。
11. LLM 请求无上下文/输出上限，且结果不缓存（刷新重复消耗）。
12. 领域规则变更无测试；迁移无旧档/缺字段/非法字段测试。
13. 新按钮缺默认/悬停/禁用/焦点状态；关键操作被遮挡；结算不展示消耗/返还/收益。
14. 假透明/水印/黑底素材入库；引用不存在的纹理/路径。
15. 一次提交混杂无关问题；临时方案无退出条件；重构改变规则未补测试。

## 8. 审查报告命名约定

- 报告落点：`docs/CODE_REVIEW_YYYY-MM-DD.md`（如 `docs/CODE_REVIEW_2026-08-06.md`）。
- 报告结构：审查范围（分级档位 + 覆盖维度）→ 机器检查结果（测试/构建/类型）→ 意见清单（按 §6 编号）→ 分级汇总（🔴/🟡/💭 计数）→ 合入门槛判定（PASS / CONCERNS / FAIL）→ 待办与下一步。
- 报告属于**过程记录**，非设计文档；归档策略按主理人指示执行，删除时遵守 §5.2 的 safe-delete 约束。

## 9. 落地路线图

| 优先级 | 动作 | 说明 |
|---|---|---|
| **P0** | CI 加 `npm test` | `.github/workflows/deploy-pages.yml` 目前只 build+deploy，不跑测试；在 build job 增加 `npm test`，测试红则失败 |
| **P1** | ESLint + Prettier | ESLint 开启：`no-explicit-any`、`@typescript-eslint/no-non-null-assertion`、`switch-exhaustiveness-check`（穷尽性，配合维度 1/3 的领域校验）；Prettier 统一格式，避免「格式化混入功能提交」（§9 红线） |
| **P2** | husky + lint-staged + PR 模板 | pre-commit 跑 lint-staged（tsc/test/lint）；PR 模板内置 §7 十五条例行确认 |

P0 完成前，人工在合入前补跑 §5.2 三项机器检查；P1/P2 由主理人排期，落地后更新本文 §9 状态。
