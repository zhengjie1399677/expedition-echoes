# 《远征余响》玩法与 LLM 叙事设计

> 状态：设计草案  
> 用途：记录当前已经达成共识的游戏循环、成长系统和 LLM 职责边界。  
> 注意：本文同时包含已实现功能与规划功能，具体状态以各节标注为准。

## 1. 核心体验

游戏的核心循环为：

```text
新的一天
→ 查看小镇新闻与任务
→ 接取当日唯一任务
→ 编成队伍、装备与准备补给
→ 远征战斗和事件
→ 获得金币、经验、材料与道具
→ 返回城镇
→ 出售、打造、购买礼物、宿舍交流
→ 结束当天
```

目标不是无限增加系统，而是先完成一个可重复体验的小闭环：

```text
接任务 → 准备 → 远征 → 结算 → 成长 → 角色反馈
```

## 2. 当前已实现

- 城镇、酒馆、宿舍、设置与远征页面。
- 三人队伍编成与前后排换位。
- 背包和角色装备管理。
- 装备攻击加成与伤害减免已进入实际战斗计算。
- 角色等级与经验。
- 多节点远征、敌人选择、撤退与通关结算。
- 宿舍独立房间、日常立绘和 GAL 式对话界面。
- 玩家自由输入、对话回顾与最近上下文。
- Mobile-Tavern 和 SillyTavern 两种聊天适配器。
- 无可用 LLM 时的本地对白降级。

## 3. 任务与每日循环

### 3.1 每日任务

- 使用游戏内天数，不依赖现实时间。
- 每天只能正式接取一次任务。
- 任务接取后当天不可随意更换。
- 完成、撤退或放弃都会消耗当天的任务机会。
- 奖励在任务完成后结算，不在点击接取时立即发放。
- 玩家主动选择“休息至次日”后刷新任务板。

### 3.2 任务奖励

每个任务可以配置：

- 金币奖励。
- 固定材料。
- 概率掉落。
- 首次完成奖励。
- 事件链推进。
- 小镇状态变化。

LLM 可以提议任务主题和叙事关联，但不能直接决定金币、属性或掉率。

## 4. 道具品质与经济

统一使用五档品质颜色：

| 品质 | 颜色 | 用途 |
| --- | --- | --- |
| 普通 | 灰色 | 基础材料、普通食物和常见装备 |
| 优良 | 绿色 | 稳定的初级强化资源 |
| 稀有 | 蓝色 | 具有明显用途差异的装备或料理 |
| 史诗 | 紫色 | 特殊配方、角色偏好礼物或事件奖励 |
| 传说 | 金色 | 稀有事件、任务链终点或收藏内容 |

材料可以：

- 出售换取金币。
- 保留用于打造装备。
- 作为任务或事件条件。

这种选择应形成实际取舍：提前出售可以解决当前金币压力，但会推迟装备打造。

## 5. 装备打造

- 配方由材料和金币组成。
- 打造结果进入现有背包。
- 装备后直接影响战斗数值。
- 攻击属性增加角色伤害。
- 防御属性减少受到的伤害。
- 后续可以增加职业限制、套装或特殊效果，但不应在首个闭环中过度扩张。

## 6. 食物与补给

食物和战斗消耗品必须分开：

- 食物：队伍行军与跨日消耗。
- 绷带、镇定剂等：战斗中主动使用。

基础规则：

- 每进入一个副本节点，全队消耗一份食物。
- 跨越新的一天时消耗城镇基础食物。
- 食物不足时仍允许继续前进，避免死档。
- 饥饿会造成生命、疲劳、攻击、防御或士气方面的惩罚。
- 玩家始终可以撤退。

料理可以提供短期效果：

- 普通干粮：只补充基础食物。
- 优良料理：少量恢复。
- 稀有料理：下一节点获得短期增益。
- 史诗或传说料理：用于特殊事件、节日或角色内容，不作为日常必需品。

## 7. 礼物、好感度与阶段化人设

金币的重要消耗出口之一是购买礼物。

礼物具有偏好标签，不同角色对同一礼物的反应不同。好感不能只靠无限赠礼提升：

- 每天或每次远征后限制有效赠礼次数。
- 普通阶段可以靠日常互动积累。
- 关键阶段必须完成个人事件才能突破。

建议的关系阶段：

| 阶段 | 人设表现 |
| --- | --- |
| 陌生 | 礼貌、克制、保持距离 |
| 熟悉 | 分享习惯、日常看法和轻量过去 |
| 信赖 | 谈论目标、恐惧、创伤和重要选择 |
| 羁绊 | 出现专属事件、更主动的关心与情感表达 |

关系阶段必须进入 LLM 提示上下文，改变称呼、语气、主动程度和允许透露的信息，而不只是替换固定台词。

## 8. LLM 的职责

### 8.1 LLM 适合负责

- 角色自然对话。
- 根据好感阶段表现不同人设。
- 对礼物生成个性化反馈。
- 对任务结果生成评论、抱怨、庆祝或安慰。
- 形成短期和长期角色记忆。
- 生成每日新闻、小镇趣事、酒馆传闻。
- 在白名单模板中提议特殊任务。
- 把多个任务和事件线索串联成连续故事。

### 8.2 LLM 不得直接负责

- 修改金币、经验、好感或属性。
- 创建任意装备数值。
- 决定未验证的奖励与掉率。
- 跳过未完成的前置条件。
- 生成不存在的地点、NPC、敌人或任务模板后直接执行。
- 直接写入游戏状态。

基本原则：

```text
游戏代码维护事实与规则。
LLM 负责表达、表演、联想和有限提议。
所有提议经过白名单校验后才能变成游戏行为。
```

## 9. 每日新闻与事件导演

每日生成器可以读取：

- 前一天完成、失败或撤退的任务。
- 当前游戏天数。
- 小镇资源和活跃事件链。
- 队伍等级与近期战利品。
- 角色关系阶段和关键记忆。
- 玩家近期关键选择。
- 天气、节日或剧情标记。

输出可以包括：

- 一条主新闻。
- 两到三条小镇趣事或传闻。
- NPC 对近期事件的看法。
- 一个经过验证后可加入任务板的特殊任务提议。
- 一个已存在事件链的后续节点。

生成结果必须保存到存档；同一天刷新页面不能重新随机生成完全不同的新闻和任务。

## 10. 结构化叙事协议

### 10.1 XML 信封示例

```xml
<game_output version="1">
  <narrative>
    <news>
      <headline>北侧水渠再次传出怪声</headline>
      <body>两名磨坊工声称，昨夜看见蓝色微光顺流而下。</body>
    </news>
    <rumor speaker="innkeeper">
      最近采购药草的人突然多了起来。
    </rumor>
  </narrative>

  <actions>
    <action type="offer_quest" template="missing_person">
      <location>north_canal</location>
      <enemy_pool>slime,bandit_scout</enemy_pool>
      <followup>herbalist_rescue</followup>
      <reward_tier>2</reward_tier>
    </action>
  </actions>
</game_output>
```

### 10.2 处理原则

游戏端不能直接信任 XML：

1. 定位 `<game_output>` 区间。
2. 清除 Markdown 代码围栏和标签外说明。
3. 尝试修正常见格式问题。
4. 解析 XML。
5. 校验版本、允许标签、属性、长度和枚举。
6. 验证任务模板、地点、敌人、NPC、奖励档位和事件状态。
7. 安全文本可以显示，非法动作必须丢弃。
8. 完全失败时使用本地模板。

即使模型原生支持结构化输出，也仍需进行语义校验。结构化能力只能保证形状，不能保证游戏逻辑正确。

## 11. 模型能力降级

不能假定用户模型支持原生结构化输出。

采用三级策略：

1. **原生结构化输出**：宿主和模型都支持时使用 Schema。
2. **普通文本＋XML**：不支持时通过提示词要求输出固定 XML。
3. **叙事降级**：XML 无法验证时，只保留新闻或对白；必要时使用本地模板。

Mobile-Tavern 后续可以提供能力查询：

```ts
interface LlmCapabilities {
  structuredOutput: boolean;
  streaming: boolean;
  maxContextTokens?: number;
}
```

格式修复优先使用本地确定性代码。只有内容完整但格式严重损坏时，才考虑再次请求模型整理。

## 12. 事件链状态

建议的通用事件链：

```text
未发现
→ 传闻出现
→ 前置任务开放
→ 前置任务完成
→ 后续事件开放
→ 分支任务或角色事件
→ 结局
→ 次日新闻与角色反馈
```

需要预留：

- 事件 ID 和版本。
- 当前节点。
- 前置条件。
- 是否看过。
- 是否失败或错过。
- 分支选择。
- 任务关联。
- 角色关联。
- 后续新闻标记。

具体事件内容可以逐步增加，但状态结构应尽早稳定。
